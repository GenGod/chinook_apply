# S26: Job Bank Direct Apply — подача отклика через аккаунт Job Bank

Статус: **DRAFT (G1 pending PO — черновик подготовлен агентом 2026-10-04, без PO не принимается)** · Версия: 0.1 · Milestone: **M6 (пер-сайт адаптеры)**
Реестр: BACKLOG B-013 · зависит от S25 (R8 браузерная инфраструктура reveal, apply-методы, dispatch_log/Approve-паттерны S8/S9).

## Проблема и цель

Прямые Job Bank-постинги с «Direct Apply» допускают подачу отклика **на самом jobbank.gc.ca** (Job Bank Plus-аккаунт). S25 дала: определение `directApply` в apply-методах, браузерную инфраструктуру (Playwright в web-контейнере, R8), UI-блок с пометкой «apply manually». Цель S26 — автоматизировать подачу: вход в аккаунт → кнопка Apply → выбор резюме аккаунта → submit, со всеми конституционными гейтами (ст. 1.2 Approve, 11.2 скриншоты, 11.3 капча-стоп).

## Жёсткие блокеры (без PO не начинается)

1. **Job Bank Plus-аккаунт PO** + creds в `.env`: `JOBBANK_SEEKER_EMAIL`, `JOBBANK_SEEKER_PASSWORD` (docker secrets; в git не попадают — проверка security-гейтом).
2. **Живые снимки пост-логин разметки** (PO логинится вручную, сохраняет HTML/скриншоты): кнопка Apply на постинге, модалка выбора резюме, экран подтверждения. **Слепые селекторы запрещены** (S23-урок; подтверждено R8-диагностикой — разметку надо снимать с живого сайта).

## Решения, не зависящие от снимков (предварительные, фиксируются на G1)

### R1. Единый браузерный флоу (наследник R8) — кандидат ✅
Весь флоу — в реальном chromium (дефолтный лаунчер S25 R8 + `CHROMIUM_EXECUTABLE_PATH` для контейнера). Селекторы флоу — в одном конфиг-объекте (fragility containment, как S23/R8). Капча (CSP Job Bank содержит hcaptcha.com — ожидаема на login/registration): `detectCaptcha` до КАЖДОГО значимого шага → немедленный стоп, аудит `skipped`, ручной фолбэк. Повторные попытки обхода запрещены.
- (откл.) HTTP-эмуляция логина — фингерпринт-гейт (урок R8: браузер проходит, fetch — нет).

### R2. Резюме — выбор из аккаунта, не загрузка — кандидат ✅
v1: PO заранее кладёт резюме в Plus-аккаунт; адаптер ВЫБИРАЕТ его детерминированным селектором (последнее загруженное / по названию). Загрузка tailored PDF в аккаунт — v2 (нужны снимки формы загрузки; риск конвертации форматов на стороне GC).
- (откл.) автозагрузка render_pdf в v1 — форма загрузки не снята; факт-чек ст. 2: содержимое резюме уже одобрено PO в рендере.

### R3. Approve/аудит/лимиты — кандидат ✅
Канал `form` в dispatch_log (контракт S9), to_address = posting URL; скриншоты before/filled/submitted (ст. 11.2) в artifacts-dir; суммарный дневной лимит S8/S9; UI-блок Direct Apply на странице вакансии показывает url + выбранный пакет перед отправкой (ст. 1.3); Send = одноразовый approve. Скрининг-вопросы (если работодатель включил) — display-only перед подтверждением; ответы НЕ генерируются (ст. 2).

### R4. Статусы ошибок — кандидат ✅
409 нет Direct Apply / уже applied; 503 браузер/креды не сконфигурированы (`JOBBANK_SEEKER_EMAIL` отсутствует — секция скрыта в UI); 502 флоу упал после навигации; капча → `skipped` (как S9).

## Тест-стратегия (когда снимки будут)

Фикстуры живых страниц (обезличенные) → integration с локальным сервером (логин-форма → redirect → apply-модалка → submit → подтверждение) + e2e через мок-роуты приложения (паттерн S9 /mock-form). Live-smoke — ручной, на реальном постинге, только после зелёных гейтов.
