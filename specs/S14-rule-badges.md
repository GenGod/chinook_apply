# S14: Rule-статусы в Jobs Explorer — бейджи и UI-фильтр

Статус: done (G6 approved 2026-09-18) · Версия: 1.0 · Milestone: **M1.5** (не-AI трек)
Источник: BACKLOG **B-004** (восстановлена PO 2026-09-18) · зависит от S2 (rule_*), S1a (UI).

## Проблема и цель

Корзины правил (relevant/review/excluded) живут в БД и API (`?rule=`), но на экране
Jobs их не видно — ценность S2 недоиспользуется. Цель: цветной бейдж статуса в строке
вакансии и селектор Rule в фильтр-баре (серверная фильтрация уже готова).

## Входные артефакты / зависимости

- `listJobs` уже возвращает `ruleStatus` (S2); API `?rule=` валидирует enum (S2).
- S1a visual-дисциплина: tbody/thead/фильтр-контролы маскируются, боксы фиксированы.

## Решение (альтернативы из brainstorm, выбор + отказ)

### R1. Подача статуса: цветной бейдж в отдельной колонке
- **(a) Колонка «Rule» с цветным бейджем** (relevant — зелёный, review — жёлтый,
  excluded — серый; null — «—») — ✅: сканируемость колонкой, единый стиль с
  source-бейджем, фиксированная ширина колонки (90px) для visual-дисциплины.
- (b) Иконка/подсветка строки — хуже при дальтонизме и в масках; (c) отдельная
  колонка текстом без цвета — теряет мгновенную считываемость. Отклонены.

### R2. Фильтр: селектор в существующем фильтр-баре
- **(a) `<select name="rule">` (All/Relevant/Review/Excluded) в форму фильтров** — ✅:
  ноль JS, GET-навигация как у source/days/sort; ширина 180px как у соседей.
- (b) Чипы-переключатели — клиентский JS ради красоты; паттерн формы уже работает.

### R3. Порядок строк: без изменений
posted DESC + canonical_hash tie-break (S2) остаётся; фильтрация по правилу — явное
действие пользователя. Сортировка «сначала relevant» — отдельный вопрос будущего
(когда появится score в S4-эпоху).

## Контракт

- `parseFilters` (page.tsx): `rule?: 'relevant'|'review'|'excluded'` из searchParams.
- Колонка Rule в таблице: бейдж с data-атрибутом `data-rule="<status>"` (e2e-хуки);
  colgroup +90px (перераспределение: Title 320→300, Actions 140→130 — сумма ≤ 1216).
- Фильтр-бар: пятое поле Rule (label + select, фиксированные 180×64).

## Acceptance criteria

1. Бейдж рендерится в каждой строке с data-rule; цвета соответствуют статусам.
2. Селектор Rule фильтрует список (e2e: rule=review сужает, все бейджи review).
3. Комбинация фильтров работает (source=adzuna&rule=relevant — e2e).
4. Visual: baseline Jobs-страницы перегенерирован (новая колонка в маскированном
   tbody, новый селектор — в маскированных филдах) → дифф «до/после» осознан;
   инверсия-доказательство (цвет бейджа/селектора) повторяется.
5. Все гейты зелёные; arch-lint чист; CI success.

## Тест-план

- **E2E (расширение s1a-jobs.spec.ts):** бейджи присутствуют и валидны; фильтр rule
  сужает и красит правильно; комбинированный фильтр; visual + инверсия.
- Unit/integration: не требуются (рендер готовых данных; фильтр уже покрыт S2-тестами).
