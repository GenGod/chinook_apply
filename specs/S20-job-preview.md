# S20: Предпросмотр вакансии перед уходом к внешнему провайдеру

Статус: implemented (все гейты зелёные 2026-09-20; merge-гейт PO) · Версия: 1.0 · Milestone: **M1.5** (не-AI трек)
Источник: BACKLOG **B-012** (PO 2026-09-20) · зависит от S1a (таблица Jobs), S7 (страница /job/[id]).

## Проблема и цель

Страница предпросмотра `/job/[id]` существует со S7 (описание из `raw`, статус-кнопки,
ссылка на оригинал), но в Jobs Explorer заголовок вакансии ведёт сразу на внешний сайт
(`job.url`, `_blank`) — путь к локальному предпросмотру из таблицы не подключён.
Дополнительно описание на `/job/[id]` обрезано 1200 символами — «предпросмотр прежде чем
уходить» не имеет смысла без полного текста.

Цель: клик по вакансии в таблице открывает локальный предпросмотр; прямой внешний
отклик из таблицы сохранён отдельной ссылкой; описание полное.

## Решение (альтернативы из brainstorm, выбор + отказ)

### R1. Точка входа — существующая страница /job/[id] (выбор PO)
- **(a) Заголовок → `/job/{id}`, рядом компактная «↗» на `job.url`** — ✅: ноль нового
  API/клиентского JS, известный паттерн; контракт B-001/S1a «Apply externally» жив.
- (b) Модал/панель поверх списка — новый клиентский UI-паттерн + `GET /api/jobs/:id`
  + superdesign; отклонено как непропорциональное (может стать отдельным инкрементом
  при реальной потребности).
- (c) Ничего не менять (страница уже есть) — отклонено: входа из таблицы нет.

### R2. Только Explorer (выбор PO)
Board-карточки уже ведут на `/job/[id]`; без изменений.

### R3. Полное описание (выбор PO)
- **(a) Снять обрезку; `<br>`/`</p>`/`</li>`/`</hN>` → переводы строк; остальные теги
  стрипаются; базовые HTML-entity декодируются; рендер `white-space: pre-line`** — ✅.
- (b) Оставить 1200 + ссылку — отклонено PO.

### R4. Безопасность: только текст
HTML провайдера никогда не рендерится как HTML — только strip → текстовый узел
(нулевая XSS-поверхность, как в S7). Внешние ссылки — `target=_blank` +
`rel="noopener noreferrer"`.

## Контракт

- Explorer (`apps/web/app/page.tsx`): заголовок — `<a href="/job/{id}">` (та же
  навигация, без `_blank`); рядом `<a data-testid="apply-external" href={job.url}
  target="_blank" rel="noopener noreferrer">↗</a>`.
- `/job/[id]` (`apps/web/app/job/[id]/page.tsx`): `descriptionFrom` без slice;
  html→text с переводами строк и entity-decode; параграф с `white-space: pre-line`.
- e2e-seed: синтетическая ON-вакансия получает `raw.description` ≈1600 символов —
  детерминированный объект теста полноты (фикстуры ≤500).

## Acceptance criteria

1. Клик по заголовку строки Explorer открывает `/job/<uuid>` (внутренняя навигация,
   без `_blank`).
2. «↗» в строке ведёт на внешний `job.url` с `_blank` + `noopener` (контракт S1a жив).
3. `/job/[id]` показывает описание вакансии полностью (>1200 символов на
   синтетике), с абзацами.
4. Весь текст описания — текстовые узлы; HTML из `raw` не исполняется (R4).
5. E2E-сьют зелёный; снапшоты без диффа (tbody замаскирован); CI зелёный.

## Тест-план

- E2E (s1a-jobs.spec.ts): тест S1a «title links open in a new tab» переписан под
  новый контракт (AC1+AC2); новый тест полноты описания (AC3) через синтетику.
- Регрессия: полный e2e-сьют (Board/метрики/снапшоты) без изменений.
