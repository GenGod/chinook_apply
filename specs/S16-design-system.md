# S16: Chinook DS v1 — дизайн-система и рестайл существующих экранов

Статус: done (CI success, ожидает G6) · Версия: 1.0 · Milestone: **M2-pre** (дизайн-трек)
Источник: PO 2026-09-18 («заняться дизайном»: система v1 + рестайл; тёмная тема как данность).
Готовит почву для S7 (дашборд/approve-флоу) — тот будет верстаться уже по токенам.

## Проблема и цель

Два экрана (Jobs, Metrics) сверстаны инлайн-значениями: цвета, размеры и состояния
размазаны по CSS-модулям и продиктованы историей инкрементов, а не системой.
Цель: **токен-слой** (палитра/типографика/сетка/компоненты) + перевод обоих экранов
на него + страница-стайлгайд `/design` для eyeball-проверки компонентов. Любой
следующий экран (S7) собирается из готовых примитивов.

## Решение (дизайн-обзор: курс зафиксирован PO, альтернативы в рамках курса)

### R1. Палитра — семантические токены на CSS-переменных
`(colors chosen; rationale: продолжение текущей темы, WCAG-AA-пары проверяются гейтом)`

### R2. Типографика — системный стек, шкала 6 ступеней
`system-ui` (без веб-шрифтов: оффлайн-скорость, детерминизм снапшотов — уже
доказано S0–S15). Шкала: 28 (H1) / 20 (section) / 16 (emphasis) / 14 (body) /
12 (aux) / 11-caps (labels). Веса: 600 заголовки и числа-метрики, 400 текст.

### R3. Сетка и размеры — 4px-грид, узаконение существующего
Контролы 36px, строки таблиц 52px, карточки метрик 112px, header 56px, поля
фильтров 180×64, бары 12px. (Уже де-факто — фиксируется как норма DS.)

### R4. Компоненты v1 (классы в `ds.module.css`, потребляются экранами)
`Button` (primary/ghost), `Badge` (status: 4 семантики + source-нейтральный),
`Table` (fixed-layout, colgroup), `Card`, `Field` (label+control), `Bar`,
`PageHeader` (title+subtitle+nav). Все с фиксированными боксами — visual-дисциплина
сохраняется. Добавляется сквозной `:focus-visible` (outline accent 2px) — a11y.

### R5. A11y-гейт: машинная проверка контраста
`tests/unit/contrast.test.ts`: пары (text-token на bg-token) ≥ 4.5:1 (WCAG AA),
крупные числа ≥ 3:1. Дизайн защищён гейтом, а не вкусом.

### R6. Стайлгайд `/design`
Секции: Palette (свотчи с именами токенов), Type (шкала), Components (кнопки,
бейджи, поля, бар, мини-таблица). Без ссылки в основной навигации (инструмент
разработки; прямые вопросы к G1).

## Контракт

- `apps/web/app/styles/tokens.css` — все CSS-переменные (импорт в root layout).
- `apps/web/app/styles/ds.module.css` — компонентные классы; Jobs/Metrics
  переводятся на `var(--…)` (разметка/поведение без изменений).
- `/design` — server-component страница-каталог.
- e2e: presence-секции; visual-гейт на оба экрана — baselines перегенерируются
  (осознанный дифф: систематизация), инверсия-доказательство обязательна.

## Acceptance criteria

1. tokens.css — единственный источник значений; в CSS-модулях экранов нет
   хардкода цветов (гейт-греп `#[0-9a-f]{6}` вне tokens.css → 0, кроме mask-констант тестов).
2. Jobs и Metrics визуально эквивалентны текущим (допустимые диффы: систематизация
   оттенков, focus-стили) — baselines обновлены осознанно, дифф описан в отчёте.
3. Контраст-гейт: все декларированные пары проходят AA.
4. `/design` рендерит секции Palette/Type/Components с именами токенов.
5. Keyboard-фокус видим на интерактивах обеих страниц (e2e: tab к Apply-кнопке,
   проверка outline).
6. Все прежние гейты зелёные; CI success.

## Тест-план

- **Unit:** contrast-гейт (R5) — вычисление WCAG-отношения из hex-пар.
- **E2E:** /design presence; фокус-стили (AC5); visual-обновление Jobs/Metrics
  + инверсия (цвет токена accent → падение).
- **Греп-гейт** хардкода цветов (AC1) — npm-script в pipeline lint-стадии.
