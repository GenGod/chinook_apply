# S18: Drag & Drop для доски откликов

Статус: accepted (G1 2026-09-18: подсветка accent; мобильная версия — отдельный эпик B-007) · Версия: 1.0 · Milestone: **M3.5**
Источник: BACKLOG **B-006** (из S7 R3) · зависит от S7 (done).

## Проблема и цель

Перемещение карточек кнопками работает, но канбан-взаимодействие естественнее
мышью: перетащил — карточка на месте. Цель: DnD между колонками `/board` с
соблюдением transition-графа; кнопки остаются как a11y-фолбэк (без изменений).

## Решение (альтернативы из brainstorm, выбор + отказ)

### R1. Транспорт: нативный HTML5 Drag & Drop
- **(a) `draggable` + `dragstart/dragover/drop` на клиентском компоненте** — ✅:
  ноль зависимостей (стек заморожен), Chromium/Firefox/Safari поддержка,
  Playwright `dragTo` тестирует честным мышепутём.
- (b) dnd-kit / react-dnd — новая зависимость ради визуальных «прилипаний»,
  которые сейчас не нужны. Отклонено (YAGNI).

### R2. Семантика дропа = transition-граф
- Дроп на колонку, недостижимую из текущего статуса → карточка возвращается,
  показывается та же ошибка, что от API (TransitionError-текст).
- Дроп на New (только из applying) → удаление строки (как кнопка Back).
- Дроп на applied_manual / applied_auto → PATCH с соответствующим channel.

### R3. Визуальный отклик: минимальный
- Колонка-цель подсвечивается бордером accent при dragover (чистый CSS-класс).
- Никаких анимаций полёта (motion-дисциплина frontend-design: движение отвечает
  действию, не украшает).

### R4. Кнопки не убираются
Канонический a11y-путь остаётся: keyboard-фокус → кнопки. DnD — параллельный
мышепуть. Visual-baseline доски не меняется (карточки замаскированы; новая
подсветка — только в состоянии dragover, которое снапшотом не тестируется).

## Контракт

- `board-card.tsx` (новый client-компонент обёртки карточки): draggable,
  dataTransfer с jobId; колонки принимают drop → вызывают существующий
  `PATCH /api/jobs/:id/status` → `router.refresh()`.
- Никаких изменений API/БД.

## Acceptance criteria

1. Карточку можно перетащить new → applying; состояние persist после reload (e2e dragTo).
2. Дроп applying → applied_manual работает (e2e).
3. Запрещённый дроп (new → interview) отклоняется: карточка остаётся в исходной
   колонке, ошибка видна (e2e).
4. Dragover-подсветка колонки присутствует (unit-уровень DOM: класс навешивается).
5. Кнопочный путь по-прежнему проходит все S7-e2e (регресс).
6. Все гейты зелёные; CI success; baseline s7-board без изменений.

## Тест-план

- **E2E:** три сценария выше + полный регресс board.spec S7.
- Unit/integration: без изменений (граф и API не меняются).
