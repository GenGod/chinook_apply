# S19: Фильтр по провинциям Канады — Jobs Explorer и Board

Статус: accepted (ревью PO 2026-09-19) · Версия: 1.1 · Milestone: **M1.5** (не-AI трек)
Источник: BACKLOG **B-009** (PO 2026-09-19) · зависит от S1 (province/remote в схеме), S1a/S14 (фильтр-бар), S7 (getBoard), S18 (DnD).

## Проблема и цель

`job.province` (2-буквенный код после нормализации S1) и `job.remote` хранятся в БД и
отображаются в строках таблицы и карточках доски, но фильтровать по ним нельзя:
`JobFilters` и `getBoard` параметра не имеют, в UI контролов нет. Профиль таргетирует
Alberta, но в потоке есть все провинции (чужие попадают в excluded-корзину S2), а
remote-вакансии — приоритетный сценарий для релокации.

Цель: серверная фильтрация списка по одной провинции/территории (13 кодов) или
«только remote» на обоих экранах списка — Jobs Explorer (`/`) и Board (`/board`).

## Входные артефакты / зависимости

- S1: `job.province TEXT NOT NULL` (код `AB`…`YT` или `''` для неизвестного/remote-only),
  `job.remote BOOLEAN`; карта `PROVINCES` в `packages/core/src/normalize.ts`.
- S1a/S14: паттерн фильтр-бара — GET-form + `parseFilters` whitelist в
  `apps/web/app/page.tsx`; whitelist-Sets в `apps/web/app/api/jobs/route.ts`.
- S7: `getBoard` (`packages/core/src/board.ts`) — колонки, карточки, totals.
- S18: DnD поверх доски (`BoardDnd`) — фильтр не должен его ломать.

## Решение (альтернативы из brainstorm, выбор + отказ)

### R1. Гранулярность: отдельные провинции/территории (выбор PO)
- **(a) 13 кодов провинций/территорий** — ✅: ложится на существующее поле без миграций;
  стандарт канадского рынка (Job Bank фильтрует по провинциям).
- (b) Макрорегионы (Запад/Онтарио/Квебек/Атлантика/Север) — новая сущность и маппинг
  ради абстракции, которой нет в данных; отклонено PO.
- (c) optgroup-иерархия — визуальная группировка без функциональной ценности при
  13 опциях; отклонено.

### R2. Тип выбора: одиночный select (выбор PO)
- **(a) `<select name="province">`** — ✅: единый паттерн с source/rule (нуль JS,
  GET-навигация); профиль таргетирует одну провинцию.
- (b) Мультивыбор (`?province=AB,BC`) — новый UI-паттерн и парсинг списков; YAGNI
  до реальной потребности.

### R3. Где: Jobs Explorer + Board (выбор PO)
- **(a) Оба экрана** — ✅: Board получает фильтр-бар впервые (компактный бар над
  доской в паттерне Explorer-бара).
- Explorer — select в существующий фильтр-бар. DnD (S18) не меняется: фильтр только
  скрывает карточки; перетаскивание видимых работает как раньше; пустые колонки
  показывают существующее Empty-состояние.
- (b) Только Explorer — отвергнуто PO; Metrics/деталка не затрагиваются.

### R4. Семантика remote: строгий матч + отдельная опция «Remote»
- **(a) Строгий `province = X`** (remote-вакансии при выборе провинции скрываются —
  у них провинция часто `''`) **+ опция «Remote»** (`remote = true`) — ✅:
  предсказуемое поведение; удалённые достижимы явной опцией.
- (b) `province = X OR remote` — фильтр «показывает province И ещё все remote» —
  сюрприз для пользователя; отклонено (правила S2 оставляют remote видимыми в
  общем потоке — фильтр не обязан повторять эту семантику).

### R5. URL-контракт: один параметр `province` с сентинелом `REMOTE`
- **(a) `?province=AB | REMOTE | ''`** — ✅: один whitelist-Set, один контрол,
  UI-состояние в одном параметре. Сентинел мапится в чистые поля на границе
  API/UI, слой запросов остаётся семантическим.
- (b) Отдельный `?remoteOnly=1` — два параметра на один select; отклонено.
- Неверное значение молча игнорируется (как у всех существующих фильтров).

### R6. Индекс
- **`CREATE INDEX IF NOT EXISTS job_province_idx ON job (province);`** в `SCHEMA_SQL`
  (packages/core/src/db.ts) — консистентно с соседними индексами; селективность
  провинции высокая, стоимость нулевая.

## Контракт

- **core, экспорт:** `PROVINCE_CODES: readonly ProvinceCode[]` (derive из `PROVINCES`),
  `type ProvinceCode` — union 13 кодов. Источник истины один — `normalize.ts`.
- **`JobFilters`** (repository.ts): `+ province?: ProvinceCode`, `+ remoteOnly?: boolean`;
  `listJobs` добавляет соответствующий `where` (параметризованный Kysely).
- **`getBoard(db, opts?: { province?: ProvinceCode; remoteOnly?: boolean })`** —
  фильтр применяется к карточкам и totals всех колонок.
- **API:** `GET /api/jobs?province=…`, `GET /api/board?province=…` — whitelist
  `PROVINCE_CODES ∪ {'REMOTE'}` (паттерн `RULES`/`SOURCES`); invalid → игнор.
- **UI Explorer:** select «Province» в фильтр-баре после Source: *All provinces /
  Remote / 13 опций «Full name (XX)»* (алфавит по полному имени); `defaultValue`
  из searchParams.
- **UI Board:** `searchParams.province` → `getBoard`; фильтр-бар над доской
  (GET-form + Apply, визуальный паттерн Explorer-бара; размещение — через
  `superdesign`: 2–3 варианта до вёрстки, по AGENTS.md правило 4).
- **e2e-хуки:** `#province` на обоих экранах.

## Acceptance criteria

1. Explorer: выбор провинции сужает список — все видимые строки имеют выбранную
   провинцию; URL содержит `province=<код>`.
2. Опция «Remote» (`province=REMOTE`) показывает только remote-вакансии;
   «All provinces» — без фильтра.
3. Комбинации работают вместе: `province` + `source` + `rule` (e2e).
4. Board: фильтр-бар фильтрует карточки и счётчики всех колонок; DnD на видимых
   карточках не сломан (регрессия S18-сьютом).
5. API `/api/jobs` и `/api/board` принимают `province`; невалидное значение → 200
   без фильтра (не 4xx — консистентно с source/rule).
6. Visual: снапшоты обоих экранов до/после осознанно обновлены; без параметра —
   ноль диффа (регрессионное отсутствие изменений).
7. Гейты: unit/integration/e2e зелёные, LSP-чистота (0 ошибок типов), arch-lint 0,
   security-аудит (claude-security) с выводом в PR, CI success.

## Тест-план

- **Unit (core):** `PROVINCE_CODES` — ровно 13, соответствует значениям `PROVINCES`;
  пустая строка не входит.
- **Integration (tests/integration, real PG):** `listJobs` — province=AB → только AB;
  remoteOnly → только remote; province+source+rule комбо; `getBoard` с фильтром —
  карточки и totals согласованы (никаких чужих провинций).
- **E2E (расширение s1a-jobs.spec.ts + board-спеки):** фильтр провинции на обоих
  экранах (URL + состав строк/карточек), REMOTE, комбинированный фильтр, invalid
  param; снапшоты до/после + нулевой дифф без параметра; DnD-регрессия существующим
  сьютом. При необходимости расширить `seed-e2e` (≥2 провинции + remote в данных).
- **Порядок (TDD):** красные тесты слоёв core → API → UI до реализации каждого шага.
