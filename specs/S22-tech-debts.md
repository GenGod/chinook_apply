# S22: Техдолг — визуальный компаратор (B-011), конвертация legacy-папок, отложенные мелочи S5

Статус: accepted (G1 — мандат PO «возьми B-011, потом конвертацию 7 legacy uuid-папок, после — отложенные мелочи из S5-отчёта», 2026-09-28) · Версия: 1.0 · Milestone: долги между инкрементами
Реестр: B-011 (BACKLOG, приоритет next) + ОВ-1 S21-report + «Отложенные мелочи» S5-report.

## Проблема и цель

Три пула накопленных долгов, мешающих доверию к гейтам и удобству эксплуатации:
1. **B-011**: дефолтный per-pixel `threshold: 0.2` в `expect.toHaveScreenshot` слеп к
   изменениям внутри тёмно-синей палитры (S19: ~279k пикселей диффа прошли как нулевые).
2. **Legacy-папки рендеров**: 7 uuid-папок (~26 файлов S6) в `data/artifacts` наряду с
   новыми датированными — просмотр неединообразен (ОВ-1 S21).
3. **Отложенные мелочи S5** (8 позиций: turbo-гейт core, tie-break listArtifacts,
   concurrent-save 23505, порядок missing-master, sequencing toggleRow, глотание
   сетевых ошибок UI, валидация dailyLimitUsd, параметризуемый seed-хелпер).

## Решения

### R1. B-011: явный threshold + перебазлайн + инверсионная проверка — ✅
- `playwright.config.ts`: `toHaveScreenshot.threshold: 0.01` (цель бэклога); если полный
  сьют нестабилен на 0.01 — откат на 0.05 с фиксацией причины в отчёте.
- Перебазлайн всех снапшотов (`e2e:update-snapshots`), затем 2 подряд зелёных прогона
  полного e2e (стабильность порога).
- Инверсионная проверка — новый скрипт `scripts/verify-visual-threshold.mjs`:
  синтетический сдвиг цвета внутри палитры на паре «baseline/shifted» через pixelmatch —
  при threshold 0.2 дифф = 0 (слепота воспроизведена), при 0.01/0.05 — дифф > 0
  (компаратор видит). Скрипт остаётся в репо как инструмент инверсионной дисциплины (S0).
- BACKLOG.md: B-011 → done.

### R2. Конвертация legacy-папок: миграционный скрипт, append, без потери файлов — ✅
Скрипт `apps/web/src/scripts/migrate-render-layout.ts`:
1. находит render-строки с content_path старой uuid-схемы (`<uuid>/<file>`);
2. по каждой: рендер заново через `renderArtifact` (append — новая версия в датированной
   папке; контент идентичен — рендер детерминирован, мастер-файл живой БД);
3. после успешного создания новых версий и проверки файлов — удаляет legacy render-строки
   (производные артефакты, не аудит-события) и осиротевшие uuid-папки;
4. dry-run по умолчанию, запись — только с `--apply`.
Откат не нужен: исходные байты выводимы из контента заново (детерминизм S6).

### R3. Мелочи S5 — TDD-пакет — ✅
- **core в turbo-гейт**: `"test": "vitest run"` в packages/core; integration-сюкит остаётся
  явным (нужна живая БД — в `pnpm test` без БД сломает локальный гейт; фиксируется в отчёте).
- **listArtifacts tie-break**: `.orderBy('version','desc')` вторым ключом; red-тест — два
  артефакта с одинаковым `created_at` → старшая версия первой.
- **concurrent saveArtifact**: retry (до 3 попыток) на 23505 с пересчётом версии; red-тест —
  `Promise.allSettled` двух saveArtifact → оба fulfilled, версии различны.
- **missing-master после eligibility**: generateDocuments проверяет job/exclusion ДО загрузки
  мастера; инъекция `opts.loadMaster` (дефолт — текущая статическая загрузка) для теста;
  red-тест — excluded job + loadMaster→null ⇒ JobNotEligibleError (409), не master-error.
- **dailyLimitUsd валидация**: explicit/env ≤ 0 или не-число → явный Error до любых вызовов;
  red-тест на opts.dailyLimitUsd = 0 и -1.
- **toggleRow sequencing**: счётчик запросов в documents-section; устаревший ответ
  (переключение на другую строку до ответа) отбрасывается; red-e2e — задержка /api/artifacts/A,
  клик A→B быстро, в превью контент B.
- **UI глотает сетевые ошибки**: generate()/toggleRow/refreshArtifacts в try/catch →
  setError(message); red-e2e — route.abort POST /generate → errorBox виден.
- **seedArtifacts-хелпер**: экспорт параметризуемого хелпера из core (job/kinds/содержимое) —
  e2e-функционально эквивалентно (зелёный сьют как верификация).

## Acceptance criteria

1. `toHaveScreenshot` имеет явный threshold (0.01 или 0.05 с обоснованием); все снапшоты
   перебазлайничаны; 2 последовательных полных e2e зелёные.
2. `verify-visual-threshold.mjs`: при 0.2 — 0 диффов на палитровом сдвиге, при выбранном
   пороге — >0 (числа в отчёте).
3. Миграция: после `--apply` в `data/artifacts` нет uuid-папок, все render-строки ссылаются
   на датированные пути, оба формата каждой пары читаются (readRenderFile),golden `render:documents` — 14 skipped.
4. `pnpm test` включает core (кол-во тестов в отчёте растёт на ~95).
5. Каждый пункт R3 имеет красный тест до фикса (кроме чистого рефакторинга seed-хелпера —
   верификация зелёными e2e).
6. Полные гейты: lint/arch-lint/typecheck/unit/integration/e2e — 0 нарушений.
